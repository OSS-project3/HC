# 단체 신청 Excel·ZIP 양식 정책

- 확정일: 2026-08-17
- 상태: 정책 확정, 양식·백엔드 구현 전
- 목적: 공지사항에 배포할 단체 신청 Excel 양식과 제출 ZIP의 계약을 정의한다.

> 이 문서는 협업 및 구현 인계를 위한 확정 정책 기록이다. 실제 구현 시 Application Source of Truth 문서와 API 명세에도 동일 내용을 전파해야 한다.

## 1. 적용 범위

- 개인 신청은 Excel을 사용하지 않는다.
- Excel은 법인·단체 신청의 구성원별 정보를 입력하는 용도로만 사용한다.
- 카드 종류, 발급 유형, 수령인, 로고·직인 등 신청 전체 공통값은 웹 신청 화면에서 받으며 Excel 열에 넣지 않는다.
- 단체 신청 1건의 구성원은 최대 100명이다.

## 2. 배포할 양식

공지사항에 다음 세 파일을 첨부한다.

```text
일반카드_단체신청_양식_v1.1.xlsx
대학교_학생증_단체신청_양식_v1.1.xlsx
고등학교_학생증_단체신청_양식_v1.1.xlsx
```

| 양식 | 적용 대상 | 열 구조 |
|---|---|---|
| 일반카드 단체 신청 | 명예한국인증, 시민증, 방문증 | 공통 11열 |
| 대학교 학생증 단체 신청 | 학생증 + `UNIVERSITY` | 공통 11열 + 학번·학과 |
| 고등학교 학생증 단체 신청 | 학생증 + `HIGH_SCHOOL` | 공통 11열, 학번·학과 없음 |

- 발급 유형(`MOBILE`/`MOBILE_AND_PHYSICAL`)은 Receiver 정책만 바꾸므로 Excel 양식을 나누는 기준이 아니다.
- 고등학교 학생증은 학번·학과를 받지 않는다.
- 내부 열 구조는 공통 11열과 대학교용 13열 두 종류지만, 사용자 혼동 방지를 위해 다운로드 파일은 세 종류로 제공한다.

## 3. Workbook 구조

### 3.1 시트

| 시트 | 역할 |
|---|---|
| `신청자명단` | 서버가 파싱하는 첫 번째 시트 |
| `작성안내` | 필수값, 입력 예시, ZIP 생성 방법, 오류 처리 안내 |
| `코드목록` | 성별·국가코드 드롭다운에 사용하는 숨김 시트 |

### 3.2 신청자명단 행 구조

```text
1행: 공통 입국날짜 | 2026-09-01
2행: 양식 버전     | 1.0
3행: 헤더
4행부터: 신청자 데이터
```

- 공통 입국날짜는 선택값이다.
- 각 행의 개별입국날짜가 있으면 개별값을 우선한다.
- 공통·개별입국날짜가 모두 비어 있으면 최종 입국날짜는 `null`이다.
- 헤더명, 열 개수, 열 순서는 공식 양식과 정확히 일치해야 한다.
- 완전히 빈 행은 무시한다.
- ID만 비어 있고 다른 셀에 값이 있는 행은 오류 처리한다.
- 수식, 매크로, 병합 셀은 허용하지 않는다.
- 1~3행과 헤더는 잠그고 데이터 영역만 편집 가능하게 만든다.
- 본문 시트에는 삭제가 필요한 예시 행을 넣지 않고, 예시는 `작성안내` 시트에 둔다.

## 4. Excel 열

### 4.1 공통 11열

| 순서 | 헤더 | 필수 | 형식·제한 |
|---:|---|---:|---|
| 1 | 사진 번호 | 자동 | `001`~`100` 텍스트, 사용자 수정 불가 |
| 2 | 영문명 | 필수 | 최대 100자 |
| 3 | 생년월일 | 필수 | `yyyy-MM-dd`, 미래 날짜 불가 |
| 4 | 출생국가 | 필수 | ISO 3166-1 alpha-2 대문자 코드. 내부 API/Java/DB 키는 `nationality` 유지 |
| 5 | 출생시간 | 선택 | `HH:mm` 또는 `HH:mm:ss` |
| 6 | 출생지역 | 필수 | 태어난 도시/지역명, 최대 200자. 예: `Chicago`, `London`, `Tokyo`, `Beijing`, `Los Angeles` |
| 7 | 성별 | 필수 | `MALE` 또는 `FEMALE` |
| 8 | 개별입국날짜 | 선택 | `yyyy-MM-dd` |
| 9 | 이메일 | 필수 | 유효한 이메일 형식 |
| 10 | 전화번호 | 필수 | E.164 국제 형식 |
| 11 | 주소 | 선택 | 최대 255자 |

### 4.2 대학교 학생증 추가 열

| 순서 | 헤더 | 필수 | 형식·제한 |
|---:|---|---:|---|
| 12 | 학번 | 필수 | 숫자 1~10자리 |
| 13 | 학과 | 필수 | 최대 100자 |

- 고등학교 학생증 양식에는 학번·학과 열을 두지 않는다.
- 일반카드 양식에도 학번·학과 열을 두지 않는다.

## 5. 사진 번호 정책

사진 번호는 회원 ID, 학번, 사번이 아니라 Excel 행과 사진 파일을 연결하기 위한 신청 내부 임시 식별자다.

- 공식 양식의 A열 헤더는 `사진 번호`다.
- 첫 신청자 행부터 `001`~`100`을 수식이 아닌 텍스트 값으로 미리 입력한다.
- 사진 번호 셀은 잠금·구분 색상·셀 메모를 적용하며 사용자가 입력하거나 수정하지 않는다.
- 사진 번호만 있는 행은 신청 데이터가 아니다.
- 영문명 등 B열 이후 신청자 정보가 하나라도 입력된 행만 검증·처리한다.
- 실제 처리되는 신청자 행의 사진 번호만 ZIP 사진과 매칭한다.
- 신청자 정보가 없는 행 번호의 사진은 여분 사진으로 전체 실패한다.
- 사진 번호는 DB에 저장하지 않는다.

## 6. 이메일·전화번호 정책

### 6.1 Excel 입력

- 모든 구성원 행에서 이메일과 전화번호를 필수로 받는다.
- 이메일은 앞뒤 공백을 제거하고 소문자로 정규화한다.
- 전화번호는 국가별 로컬 형식을 따로 저장하지 않고 E.164 국제 형식으로 정규화한다.
- E.164 저장 예: 대한민국 `+821012345678`, 미국 `+12025550123`.
- 전화번호 셀은 텍스트 형식으로 입력한다.
- 전화번호의 국가를 구성원의 국적으로 추측하지 않는다.
- 국제 문자 발송을 고려해 모든 국가 번호를 같은 형식으로 저장한다.
- E.164 국제번호는 국가코드를 포함하며 최대 15자리다.
  - 참고: https://www.itu.int/rec/T-REC-E.164-202602-I/en

### 6.2 중복

- `User.email`은 계정 식별자이므로 전역 UNIQUE다.
- `ApplicationMember.email`과 `ApplicationMember.phone`은 전역 UNIQUE로 만들지 않는다.
- 동일인이 여러 카드를 발급받거나 고등학생 구성원이 보호자 연락처를 공유할 수 있기 때문이다.
- 이메일·전화번호가 같은 카드가 여러 개면 연락처 조회 API는 단건을 임의 선택하지 않고 카드 목록을 반환한다.
- Excel의 사진 번호는 양식에서 001~100으로 고정되어 중복되지 않는다.

## 7. 사진 매칭 및 검증

### 7.1 매칭

```text
Excel 사진 번호: 001
사진 파일: 001.jpg
```

- 사진 파일명은 `사진 번호 + 확장자` 형식이다.
- 허용 확장자는 `jpg`, `jpeg`, `png`다.
- 확장자 대소문자는 구분하지 않는다.
- `001.jpg`와 `001.png`가 함께 있으면 동일 사진 번호 중복으로 전체 실패한다.
- 실제 입력된 행의 사진 번호에 대응하는 사진이 없으면 전체 실패한다.
- 실제 입력된 행에 없는 번호의 여분 사진이 있으면 전체 실패한다.

### 7.2 사진 파일

- 구성원 사진 1개 최대 크기: 2 MiB.
- MIME, 바이너리 Signature, 이미지 디코딩을 검증한다.
- EXIF Orientation을 반영한 표시 기준 최소 해상도는 300×400이다.
- 권장 해상도는 600×800~1200×1600이다.

## 8. ZIP 구조

```text
submitFile.zip
├── members.xlsx
├── 001.jpg
├── 002.jpg
└── 003.png
```

- ZIP 루트에 `.xlsx` 파일이 정확히 1개 있어야 한다.
- 구성원 사진도 모두 ZIP 루트에 둔다.
- Excel 파일명은 사용자가 변경해도 되지만 `.xlsx` 확장자는 유지해야 한다.
- ZIP에 상위 폴더 자체를 넣지 않는다.
- 학교·기관 로고와 직인은 ZIP에 넣지 않고 웹 신청 화면의 별도 multipart 파일로 업로드한다.
- `__MACOSX`와 `.DS_Store` 같은 운영체제 부산물은 무시한다.
- 하위 디렉터리의 파일은 사진으로 인정하지 않는다.

## 9. 파일 크기

| 대상 | 최대 크기 |
|---|---:|
| 단체 신청 구성원 | 100명 |
| Excel `.xlsx` | 5 MiB |
| 구성원 사진 1개 | 2 MiB |
| 로고 1개 | 5 MiB |
| 직인 1개 | 5 MiB |
| 제출 ZIP | 250 MiB |
| ZIP 압축 해제 후 전체 | 250 MiB |
| ZIP 내부 유효 파일 | 110개 |
| 전체 multipart 요청 | 270 MiB |

- ZIP 내부 유효 파일 수는 디렉터리, `__MACOSX`, `.DS_Store`를 제외한 파일을 기준으로 센다.
- 최대 100명일 때 사진 100개와 Excel 1개를 포함하고도 9개의 안전 여유를 둔다.
- 압축된 ZIP 크기뿐 아니라 각 엔트리 및 압축 해제 후 누적 크기를 읽는 도중 제한해야 한다.
- 압축 폭탄과 메모리 고갈을 방어해야 한다.

## 10. 검증·실패 정책

- 입력 오류가 하나라도 있으면 일부 성공 없이 신청 전체를 실패시킨다.
- 가능한 모든 행 오류를 수집해 한 번에 `errors[]`로 반환한다.
- 다음 항목은 모두 전체 실패 사유다.
  - 지원하지 않는 양식 버전
  - 헤더명·열 개수·열 순서 불일치
  - 필수값 누락 또는 형식 오류
  - 사진 번호 변조·누락 또는 중복
  - 사진 누락·중복·여분
  - 파일 종류·크기·이미지 검증 실패
  - 일반·고등학교 양식에 학번·학과 열이 존재
  - 대학교 양식에 학번·학과가 누락
  - 손상된 Excel 또는 ZIP
- 구버전 양식에는 `공식 공지사항에서 최신 신청 양식을 다시 내려받아 작성해 주세요.`라고 안내한다.

## 11. 공지사항 배포 정책

- 공지사항에 현재 지원하는 최신 버전의 세 양식을 첨부한다.
- 공지 본문과 Excel `작성안내` 시트에 동일한 핵심 주의사항을 적는다.
- 양식이 변경되면 파일명과 2행의 양식 버전을 함께 올린다.
- 서버는 지원하는 버전만 허용하고 구버전을 조용히 해석하지 않는다.
- 사용자는 양식을 작성한 뒤 Excel과 사진을 하나의 ZIP으로 압축해 신청 화면에 첨부한다.

## 12. 카드 조회 연계 정책

구성원 이메일·전화번호를 받는 목적에는 발급 카드 조회와 국제 안내 발송이 포함된다.

### 12.1 연락처 조회

- 이메일과 전화번호를 모두 필수로 입력한다.
- 정규화된 두 값이 모두 일치하는 발급 카드 목록을 반환한다.
- 여러 카드가 일치하면 사용자가 목록에서 선택한다.
- 입력값 중 어느 것이 틀렸는지는 응답에서 구분하지 않는다.

### 12.2 카드번호 조회

- `ApplicationMember.cardNumber`는 전역 UNIQUE다.
- 카드번호만으로는 기본 발급 정보까지만 확인한다.
- 개인 모바일 카드 이미지·파일을 조회하거나 내려받기 전에는 저장된 이메일 인증을 거친다.
- 로그인 사용자가 자기 신청의 카드를 조회할 때는 기존 소유권 검증을 사용한다.
