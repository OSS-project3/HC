## 현재까지 수행한 조사

- 전체 프론트 라우트와 주요 컴포넌트 확인
- 버튼, 링크, 폼 제출, API 호출, mock/localStorage 사용 경로 추적
- Application, Auth, User, Review, Board 관련 백엔드 Controller·DTO·문서 대조
- 주요 16개 라우트를 PC `1440×1000`, 모바일 `390×844`, 태블릿 `768×1024`에서 초기 렌더링 확인
- 세 화면 크기 모두 초기 페이지 기준 문서 전체의 수평 오버플로 없음 확인
- `npx tsc --noEmit` 통과 확인

주의: 파일 선택 이후, 모달을 연 상태, 긴 다국어 문구, API 실응답이 주입된 상태 등 모든 상호작용 상태의 시각 검증까지 끝난 것은 아니다.

## 기능별 진행 메모

### 신청

- 최종 검토 화면과 구역별 수정 버튼은 이미 구현되어 있다.
- 단계별 필수값 검증 없이 다음 단계로 이동할 수 있고, 파일 단계도 필수 파일이 없어도 진행된다.
- 개인 신청에서 입력받은 신청자 이메일을 API 요청에 포함하지 않아 백엔드가 회원 이메일로 fallback한다.
- 단체 신청 수량을 사용자가 직접 입력하지만 확정 정책은 유효한 Excel 신청자 수가 카드 수량이다.
- 학생증 단체 신청에서 학교 직인은 선택인데 프론트 제출 전 검사가 직인을 필수로 요구한다.
- 사진·로고·직인의 5 MiB, 확장자, MIME, 실제 이미지, 최소 해상도 안내와 사전 검증이 부족하다.
- ZIP의 Excel ID·사진 파일명 규칙, 중복·누락·여분 사진, `001` 텍스트 ID 규칙 안내가 없다.
- 단체 Excel 양식 다운로드가 없다. 백엔드 템플릿 API도 현재 확인되지 않았다.
- 파일은 미리보기·교체·삭제할 수 있지만 업로드 진행률과 실패 후 재시도 상태가 없다.
- 새로고침 후 파일명 메타데이터만 남고 실제 `File`은 복구되지 않아 마지막 제출에서 재선택 오류가 발생할 수 있다.
- 디자인을 고르는 것처럼 보이지만 실제 신청 요청에는 `cardDesignId`가 포함되지 않고 관리자가 나중에 배정한다.
- 완료 화면의 입금자명 입력은 저장·전송되지 않는다.

### 제작 내역·모바일 카드

- 마이페이지 제작 내역은 localStorage이며 백엔드 신청 목록·상세 API는 설계만 있고 구현되지 않았다.
- 제작 내역 행에서 상세로 진입할 수 없다.
- 상태 의미, 진행 이력, 반려 사유, 재업로드, 취소, 수령인·배송, 완성 카드 다운로드가 연결되지 않았다.
- 프론트와 백엔드의 신청 상태 enum이 다르다.
- 개인 사진 반려 재업로드 화면은 반려 사유를 보여주지 않고 단체 `submitFile` 재업로드 흐름은 없다.
- 재업로드 성공 후 상태를 다시 조회하지 않아 기존 `PHOTO_REJECTED` 화면에 남을 수 있다.

### 회원·인증

- 회원 조회·수정·탈퇴 백엔드 API는 있고 API 사용자 경로에서 사용한다.
- 마이페이지 요약에 전화번호·주소가 표시되지 않으며 프로필 요청의 로딩·실패·저장 성공 상태가 없다.
- local/demo 사용자의 회원정보 수정은 실제 저장되지 않는다.
- 이메일·비밀번호 로그인/가입, 계정 찾기는 mock이며 백엔드 실제 인증은 OAuth 중심이다.
- 토큰 갱신 최종 실패 시 사용자 상태 제거와 로그인 재이동이 없어 만료된 세션이 로그인 상태처럼 보일 수 있다.
- 로컬 Vite에는 `/api`, `/oauth2`, `/login/oauth2` proxy가 없다.

### 후기

- 백엔드 Review CRUD·검색·필터 API가 있지만 프론트 후기 기능은 모두 localStorage다.
- 프론트 필터·검색은 로컬 데이터 기준으로 동작한다.
- 후기 작성 자격이 있는 신청유형·카드종류를 먼저 조회하고 선택하는 흐름이 없다.
- 마이페이지 내 후기도 localStorage이며 서버의 내 후기 조회 API가 없다.
- API 연결 후 필요한 로딩·빈 목록·실패·재시도·중복 제출 상태가 없다.

### 공지·FAQ·문의·행사

- 공지·FAQ는 localStorage/정적 데이터다. 현재 작업트리의 Board 백엔드는 프론트와 연결되지 않았다.
- 공지 첨부파일은 실제 저장 파일이 아니라 브라우저에서 만든 텍스트 data URL이다.
- 문의 작성·목록·상세·관리자 답변은 localStorage이며 백엔드 Inquiry API가 없다.
- 문의 등록 후 방금 등록한 문의 상세가 아니라 고객지원 화면으로 이동한다.
- 비회원 문의 허용 여부와 비회원 답변 조회 정책은 확인이 필요하다.
- 행사는 정적/로컬 데이터이며 상세는 URL 없는 모달이다.
- 카카오 상담 링크가 실제 채널이 아닌 일반 주소이고, 개인정보처리방침·이용약관은 placeholder 상태다.

### 관리자 의존성

- 관리자 신청 승인·반려·미리보기·출력·상태 갱신은 localStorage 중심이다.
- 실제 운영 처리 경로가 연결되지 않으면 사용자 마이페이지와 모바일 카드도 실데이터로 진행될 수 없다.

## 현재 결론

초기 화면 구성과 기본 반응형 레이아웃은 비교적 폭넓게 구현되어 있지만, 운영 가능한 하나의 발급 흐름으로는 아직 연결되지 않았다. 우선 확인·해결할 항목은 OAuth 약관, 학생증 학교구분·방향, 비로그인 mock 신청, 조회 계약, 모바일 카드 데모 fallback, 상세 검증 오류, 마이페이지 실데이터 연결이다.
