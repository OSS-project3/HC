# Bulk 단체 신청 검증 규칙 (Validation Rules)

**작성일**: 2026-07-20  
**상태**: 사장님 확인 필요 (❓로 표시된 항목)  
**목적**: ValidationService에서 ZIP/Excel/이미지를 검증할 때 사용할 규칙 정의

---

## 1️⃣ 필수 컬럼 누락 검증

### 규칙

```
엑셀 첫 번째 행(Row 1)이 헤더여야 함
필수 헤더: ID, 영문이름, 국적, 생년월일, 출생시간, 출생지역, 성별, 한국입국일, 주소
(한자이름은 관리자가 별도로 지정하므로 포함 안 함)
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 현재 |
|------|------|------|
| 헤더 행 | 헤더가 정확히 1행 고정인가? | ✅ (1행) |
| 헤더 이름 | 헤더명이 정확히 위 9개인가? (공백/대소문자 구분?) | ✅ (정확히 9개) |
| 컬럼 순서 | A~I 순서 고정인가? (섞여 있어도 되나?) | ❓ |
| 숨겨진 컬럼 | 숨겨진 컬럼이 있으면 무시하나? | ❓ |
| 빈 행 | 헤더 사이에 빈 행이 있으면? | ❓ |

### 에러 처리

```
- 헤더 행 없음 → EXCEL_INVALID_HEADER
- 필수 컬럼 누락 → EXCEL_INVALID_HEADER
- 컬럼 순서 다름 → EXCEL_INVALID_HEADER (또는 자동 매칭?)
```

## 2️⃣ 필수값 누락 검증

### 규칙

```
9개 컬럼 모두 필수 (NULL/빈값 불가)
컬럼: ID, 영문이름, 국적, 생년월일, 출생시간, 출생지역, 성별, 한국입국일, 주소
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 현재 |
|------|------|------|
| 값 존재 | 9개 컬럼 모두 필수인가? | ✅ (확정) |
| 공백 처리 | "  " (공백만)은 값이 있는 건가? 없는 건가? | ❓ |
| 0 값 | ID=0 은 유효한가? | ❓ |
| 음수 | ID=-1 같은 음수는? | ❓ |

### 에러 처리

```
Row N, Column "컬럼명": 필수값이 비어있습니다
→ ROW_MISSING_REQUIRED_FIELD
```

## 3️⃣ 날짜 형식 검증

### 규칙 - 생년월일 (Birth Date)

```
형식: YYYY-MM-DD (고정)
범위: 가능한 모든 과거 날짜
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 예시 | 현재 |
|------|------|------|------|
| 형식 | YYYY-MM-DD 고정인가? | 2000-01-15 | ✅ |
| 잘못된 날짜 | 존재하지 않는 날짜는? | 2026-13-45 | ❓ |
| 미래 날짜 | 미래 날짜는 가능한가? | 2099-12-31 | ❓ |
| 너무 먼 과거 | 1800년 같은 먼 과거는? | 1800-01-01 | ❓ |
| 현재 날짜 | 오늘 날짜는 가능한가? | 2026-07-20 | ❓ |

### 규칙 - 한국입국일 (Entry Date)

```
형식: YYYY-MM-DD (생년월일과 동일)
범위: 생년월일 이후, 오늘 이전 또는 오늘 포함

주의: 발급일(Card Issuance Date)은 사용자가 입력하지 않음
      → 관리자가 카드 발급 시 시스템에서 자동 생성
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 현재 |
|------|------|------|
| 생년월일과 관계 | 생년월일 이후여야 하나? | ❓ |
| 미래 날짜 | 미래 입국일은 가능한가? | ❓ |
| 생년월일 == 입국일 | 같은 날짜는 가능한가? | ❓ |

### 에러 처리

```
Row N, Birth Date: 날짜 형식이 올바르지 않습니다 (YYYY-MM-DD 필요)
Row N, Birth Date: 유효하지 않은 날짜입니다 (예: 2026-13-45)
Row N, Birth Date: 미래 날짜는 불가능합니다
```

## 4️⃣ 국적 코드 형식 검증

### 확인 사항 (사장님에게 물어봐야 함 - 가장 중요)

| 항목 | 질문 | 옵션 A (2자) | 옵션 B (3자) | 옵션 C (전체) |
|------|------|----------|----------|------------|
| 형식 | 어떤 형식? | US, KR, CN | USA, KOR, CHN | United States |
| 대소문자 | 대소문자 구분하나? | US / us / Us | USA / usa / Usa | |
| 유효성 | ISO만 인정? | ✅ | ✅ | ✅ |

### 규칙 (확정 후 적용)

```
[선택한 형식에 맞춰 작성]

예: ISO 3166-1 alpha-2 (2자, 대문자)
  → US, KR, CN, JP, DE, FR, ...
```

### 에러 처리

```
Row N, Nationality: 유효하지 않은 국적 코드입니다 (ISO 2자 대문자: US, KR, ...)
```

## 5️⃣ 출생시간 (Birth Time) 검증

### 규칙

```
형식: HH:MM (24시간 형식)
범위: 00:00 ~ 23:59
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 예시 | 현재 |
|------|------|------|------|
| 형식 | HH:MM 고정인가? | 14:30 | ✅ |
| 초단위 | SS도 포함하나? | 14:30:45 | ❓ |
| 자정 | 00:00은 유효한가? (오전 12시) | 00:00 | ✅ |
| 24:00 | 24:00은 가능한가? (자정) | 24:00 | ❓ |

### 에러 처리

```
Row N, Birth Time: 시간 형식이 올바르지 않습니다 (HH:MM 필요)
Row N, Birth Time: 유효하지 않은 시간입니다 (00:00 ~ 23:59)
```

## 6️⃣ 성별 (Gender) 검증

### 규칙

```
유효한 값: M (Male), F (Female), O (Other)
대소문자 무시 가능
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 현재 |
|------|------|------|
| 코드 | M/F/O 맞나? | ✅ (가정) |
| 전체명 | Male/Female/Other도 가능? | ❓ |
| 기타 | 그 외 값도 인정? (X, U 등) | ❓ |
| 대소문자 | m/f도 가능? (m도 M으로 처리?) | ❓ |

### 에러 처리

```
Row N, Gender: 유효하지 않은 성별입니다 (M/F/O 중 선택)
```

## 7️⃣ 사진 존재 여부 검증

### 규칙

```
ZIP에 ID.jpg 또는 ID.jpeg 파일이 존재해야 함
(대소문자 무시, 예: 1.jpg, 1.JPG, 1.Jpg 모두 가능)
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 설정 | ID=1 기준 | 현재 |
|------|------|----------|------|
| 파일명 | 1.jpg 또는 1.jpeg | 1.jpg, 1.jpeg | ✅ (확정) |
| 확장자 | JPG만 (PNG는 나중에 추가) | 1.jpg, 1.jpeg | ✅ (확정) |
| 대소문자 | 대소문자 무시 | 1.JPG, 1.Jpg | ✅ (확정) |
| 파일명 형식 | 정확히 ID만? | 1.jpg만 | ✅ (확정) |
| 해상도 | 최소 해상도? | 최소 200x200 | ✅ (확정) |
| 파일 크기 | 최대 크기? | 최대 10MB | ✅ (확정) |

### 에러 처리

```
Row N, ID=1: 사진 파일을 찾을 수 없습니다 (1.jpg 또는 1.jpeg 필요)
Row N, ID=1: 사진 형식이 지원되지 않습니다 (JPG/JPEG만 가능)
Row N, ID=1: 사진 해상도가 너무 낮습니다 (최소 200x200)
Row N, ID=1: 사진 파일이 너무 큽니다 (최대 10MB)
```

## 8️⃣ 중복 ID 검증

### 규칙 - 같은 ZIP 내에서

```
ID 값이 중복되면 안 됨
```

### 규칙 - 전체 시스템에서

```
같은 사용자의 다른 신청에서 같은 ID?
→ 이건 검증할 필요 없나?
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 현재 |
|------|------|------|
| 같은 ZIP 내 | ID 1,2,3,1 같으면? | ❓ |
| 시스템 전체 | 다른 사용자 신청과 ID 중복? | ❓ |

### 에러 처리

```
Row 5, 10: ID "1"이 중복되었습니다
```

## 9️⃣ 사진-엑셀 매칭 검증

### 규칙

```
엑셀의 모든 ID에 대응하는 사진이 있어야 함
```

### 확인 사항 (사장님에게 물어봐야 함)

| 항목 | 질문 | 현재 |
|------|------|------|
| ID 없는 사진 | 1.jpg가 있는데 ID=1이 엑셀에 없으면? | ❓ (경고? 에러?) |
| 사진 없는 ID | ID=2인데 2.jpg가 없으면? | ✅ (에러) |
| 순서 | 엑셀 순서와 사진 순서 상관없나? | ✅ (상관없음) |

### 에러 처리

```
Row N, ID=5: 사진 파일을 찾을 수 없습니다 (5.jpg 필요)

[선택사항] 경고 메시지:
5.jpg 파일이 엑셀에 매칭되지 않습니다 (ID=5가 없음) → 무시됨
```

## 🔟 30% 이상 실패 기준

### 규칙

```
failedCount / totalCount >= 0.30 → 전체 거절
```

### 확인 사항 (사장님에게 물어봐야 함)

| 50명 기준 | 실패 인원 | 비율 | 결과 | 해석 |
|---------|---------|------|------|------|
| 14명 실패 | 14 | 28.0% | ✅ 승인 | 30% 미만 → 가능 |
| **15명 실패** | **15** | **30.0%** | **❓ ?** | **정확히 30%는?** |
| 16명 실패 | 16 | 32.0% | ❌ 거절 | 30% 초과 → 불가 |

### 경계값 처리 (사장님에게 물어봐야 함)

```
질문 1: 정확히 30.0%일 때는?
  → >= 30% ? (30% 포함 = 거절)
  → > 30% ? (30% 제외 = 승인)

질문 2: 소수점 처리는?
  → 14.5명? 올림? 버림?
  
질문 3: 최소 신청 인원은?
  → 1명 신청 가능? 아니면 최소 2명?
```

### 에러 처리

```
검증 실패율이 30% 이상입니다 (14명 실패 / 50명 신청)
엑셀을 수정한 후 다시 업로드하세요
```

## 📋 정리 표 - 사장님에게 확인 요청

| 항목 | 확인 필요 사항 | 우선순위 |
|------|--------------|---------|
| 1. 필수값 | 공백만 있으면 필수값으로 간주? | 중간 |
| 2. 날짜 | 미래 날짜 가능? 너무 먼 과거? | 중간 |
| 3. **국적** | **2자? 3자? 대소문자?** | **높음** |
| 4. 시간 | 초 단위? 24:00 가능? | 낮음 |
| 5. 성별 | M/F/O만? 대소문자 자동 변환? | 중간 |
| 6. 사진 | 확장자 (JPG/JPEG만)? 해상도/크기 제한? | 중간 |
| 7. 중복ID | 같은 ZIP 내만 체크? 전체 시스템? | 중간 |
| 8. 매칭 | 여분 사진은 경고/무시? | 낮음 |
| 9. **30% 기준** | **정확히 30%일 때는? 올림/버림?** | **높음** |

## 🎯 구현 전 최종 확인

이 규칙들이 정해지면 `ValidationService.validate()` 메서드에 다음과 같이 적용됩니다:

```java
public ValidationResult validate(MultipartFile excelZip, MultipartFile photoZip) {
    // 1. 두 ZIP 추출
    //    - excelZip: applicants.xlsx 파일 포함
    //    - photoZip: 1.jpg, 2.jpg, 3.jpg ... 포함
    
    // 2. Excel 파싱
    //    - 필수 9개 컬럼 확인
    //    - 필수값 확인
    
    // 3. 각 Row 검증
    //    - 날짜 형식 (생년월일, 한국입국일)
    //    - 시간 형식 (출생시간)
    //    - 국적 코드 (ISO)
    //    - 성별 (M/F/O)
    //    - ID 중복 확인
    
    // 4. 이미지 검증
    //    - 파일 존재 여부 (ID.jpg)
    //    - 파일 형식 (JPG/PNG)
    //    - 해상도/크기
    //    - 매칭 여부 (Excel ID ↔ Photo filename)
    
    // 5. 전체 실패율 확인
    //    - failedCount / totalCount >= 0.30 ? 전체 거절 : 유효한 것만 반환
    
    return result;
}
```
